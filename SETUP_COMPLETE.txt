KEY ARCHITECTURAL DECISIONS:
================================================================================

  Authentication:       OIDC/OAuth 2.0 (Microsoft Entra ID, Google)
                        Provider-agnostic abstraction
  
  Database:            PostgreSQL (production), H2 (development)
                       Versioned migrations
  
  Scaling:             Horizontally scalable with Kubernetes
                       All state in database (no in-memory source of truth)
  
  Authorization:       Server-side enforcement (not UI-based)
                       Three roles: EMPLOYEE, MANAGER, ADMIN
  
  Audit Trail:         Immutable logs with timestamp, actor, action, values
  
  Time Recording:      Multiple periods per day, overnight support
                       Break calculated from gaps
                       Server time authoritative
  
  Timesheet Workflow:  Calendar month as period
                       DRAFT → SUBMIT → APPROVED/REJECTED or RESUBMIT
                       Approved timesheets immutable

BUSINESS RULES HIGHLIGHTS:
================================================================================

  • Only active employees can log in
  • Email must match between IAM and application database
  • Managers can view direct reports or all department employees
  • Timesheets can only be submitted after calendar month is complete
  • Rejected timesheets return to DRAFT status for correction
  • Approved timesheets become immutable for all users
  • All significant operations logged to immutable audit trail
  • Time entries editable only while timesheet is DRAFT
  • Admins cannot directly modify time records (manager responsibility)
  • Admins cannot approve timesheets (manager responsibility)
